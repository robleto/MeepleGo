# Design Tokens

MeepleGo uses a pragmatic token approach. This initial reference documents the rating color scale which appears in rating chips, badges, and analytics.

## Rating Scale (1 – 10)

| Rating | Tailwind Classes                            | Semantic Label |
| ------ | ------------------------------------------- | -------------- |
| 1      | `bg-red-600` / `text-red-600` subtle shades | Awful          |
| 2      | `bg-orange-600`                             | Bad            |
| 3      | `bg-amber-600`                              | Poor           |
| 4      | `bg-yellow-600`                             | Below Average  |
| 5      | `bg-lime-600`                               | Average        |
| 6      | `bg-green-600`                              | Above Average  |
| 7      | `bg-emerald-600`                            | Good           |
| 8      | `bg-teal-600`                               | Very Good      |
| 9      | `bg-cyan-600`                               | Great          |
| 10     | `bg-sky-600`                                | Masterpiece    |

> Solid vs subtle variants are generated via helper functions in `getRatingSolidClass` and `getRatingSubtleClass`.

## Usage Guidelines

- Use solid variant for primary score emphasis (e.g., prominent rating chips).
- Use subtle variant in dense UI (tables, lists) to reduce visual noise.
- Provide accessible labels (e.g., aria-label: `8/10 Very Good`).
